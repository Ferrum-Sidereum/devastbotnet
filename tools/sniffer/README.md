# Master Client Sniffer (Tampermonkey)

Read-only tap для Phase 0. Перехватывает WebSocket-кадры в окне оператора и отправляет их локальному приёмнику.

## Установка

1. Запустить приёмник:
   ```bash
   npm run recorder
   ```
2. Открыть Tampermonkey → Create a new script → вставить содержимое `master-client-sniffer.user.js` → сохранить.
3. Открыть `https://devast.io`, зайти в игру.
4. В консоли должно появиться:
   ```
   [devast-tap] installed, session mp-... , ingest ws://127.0.0.1:8787/ingest
   [devast-tap] in=120 out=80 queue=0 dropped=0 transport=open
   ```

Если `transport` не `open`:

- приёмник не запущен или порт занят;
- браузер блокирует `ws://127.0.0.1` (редко: loopback считается trustworthy);
- CSP страницы блокирует WebSocket. Тогда скрипт автоматически переключится на `GM_xmlhttpRequest` POST на `http://127.0.0.1:8787/ingest` (loopback, без CORS-ограничений);
- игра использует Web Worker для сети — `window.WebSocket` не увидит трафик. Это известное ограничение, см. §17 Architecture v2.

## Управление

В консоли страницы:

```js
__devastTap.mark("axe-on-tree")   // метка для корреляции с исходящим пакетом
__devastTap.stats()               // счётчики, очередь, транспорт
__devastTap.flush()               // принудительная отправка
__devastTap.disable()             // выключить захват
__devastTap.enable()              // включить обратно
```

Полное отключение при следующей загрузке:

```js
localStorage.__devastTapOff = "1"
```

Токен (если приёмник запущен с `--token`):

```js
localStorage.__devastTapToken = "secret"
```

Скрипт добавит его в query и заголовок. Токен читается из localStorage, а не хардкодится.

## Что именно перехватывается

- **Исходящие** — `WebSocket.prototype.send` патчится один раз. Нативный `send` вызывается с исходными аргументами; payload не меняется и не дублируется. Собственный tap-сокет помечен `__devastTapInternal` и пропускается.
- **Входящие** — `message`-listener, добавляемый до того, как игра получит экземпляр; плюс хуки `onmessage` и `addEventListener("message")` для сокетов, созданных позже. `onmessage` игры вызывается штатно.
- **Действия** — `keydown` (без auto-repeat), `mousedown`, `mouseup`, `wheel` (троттлинг 100 мс), плюс ручные метки.

Формат кадра: `seq`, `ts` (wall clock), `agentTs` (performance.now), `dir`, `kind`, `len`, `b64` (полный payload до 1 МБ), `hex` (первые 512 Б), `views` (little-endian i8/i16/i32/f32/f64, первые 256 Б).

`b64` — транспорт, не преобразование. Приёмник пишет исходные байты в `frames.bin`, поэтому анализ не зависит от JSON-представления.

## Ограничения и безопасность

- Скрипт **не отправляет** пакеты в игровой сокет. Это гарантия ADR-008: основной аккаунт не автоматизируется.
- Патч `WebSocket.prototype.send` глобальный для страницы, но обработчик только читает кадр и вызывает нативный `send`; сторонние сокеты (аналитика, CDN) не ломаются, хотя их кадры тоже попадут в дамп. Если это мешает, отфильтруйте по `url` в анализаторе.
- Собственный tap-сокет создаётся из сохранённого нативного конструктора и не инструментируется — рекурсии нет.
- Blob-кадры читаются асинхронно; `seq` присваивается в момент получения, поэтому порядок восстанавливается по `seq`, даже если запись пришла не по порядку.
- Дампы содержат ники и клан-теги. Не публиковать `sessions/`.
- Приватность: URL передаётся без query (redaction на приёмнике), user-agent усечён, заголовки авторизации не читаются.
