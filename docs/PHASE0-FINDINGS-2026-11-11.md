## `0x14` — entity batch

Факт: все 566 кадров имеют структуру `2 + 20×N` байт.

```
[0x14][key][20-byte record]×N
```

- `key = 0xae` во всех наблюдаемых кадрах; гипотеза — XOR/обфускация записи.
- 437 кадров `N=1`, шаг ~178 мс (p90 542 мс) — heartbeat/одна запись.
- 129 кадров `N=2…26` — пачки сущностей.
- После XOR ключом записи дают повторяющиеся пары и малые u16; поля не подтверждены.

Схема: `opcodes.s2c.entity_batch` (`status: hypothesis`).

## Handshake / token (blocked)

- Реальный WS URL: `wss://frankfurt3.devast.io/frankfurtsurvival2?<256 hex>`; `Origin: https://devast.io`, стандартные `Sec-WebSocket-*`, без cookies.
- Прямое headless-подключение без query-токена даёт `socket hang up`.
- Токен не найден отдельным HTTP fetch/XHR: в захвате видны только документ, скрипты, картинки и аудио. Похоже, он генерируется клиентским JS (обфусцированный бандл).
- `0x47` command-семейства: `0xc8` (8B move), `0xcc` (6B action), `0xce` (4B quick), `0xd1` (86–135B join/auth). Схема обновлена, payload теперь после байта команды.
- Следующий блокер: получить/сгенерировать токен. Варианты: breakpoint на `WebSocket` constructor с инспекцией caller-scope; либо воспроизвести JS-генератор; либо использовать браузер как token oracle и проверить одноразовость токена.
